02 — Process

How a release gets to “go”.

The QA lifecycle I run on every project, from the first change request to post-release checks.

  1. 01✓

    Plan

    Effort estimates for change requests, risk analysis, and testing prioritised by business impact.

  2. 02✓

    Design

    Test plans, scenarios and cases, traced back to requirements through an RTM.

  3. 03✓

    Execute

    Functional, regression, integration, API, database and performance testing on web, desktop and mobile.

  4. 04✓

    Track

    Defects logged, prioritised and driven to resolution with developers in Jira.

  5. 05✓

    Accept

    UAT coordinated with clients and taken through to formal sign-off.

  6. 06✓

    Release

    Go/no-go decision, deployment through Azure DevOps pipelines, then post-release verification.
